# Проверка перед приёмкой UX — 23.10.2026

Ветка: `frontend/1c-inspired-redesign`; проверены изменения до `1a75157` и связанные пути сохранения, проведения и восстановления ввода.

## Подтверждённые проблемы и исправления

| Приоритет | Проблема | Исправление |
|---|---|---|
| P1 | Одновременные изменение черновика оплаты и проведение могли оставить оплату на 200 при кассовой операции на 100. Ошибка существовала до последних UX изменений. | Изменение и удаление черновика блокируют оплату до проверки статуса, как проведение. Поздняя операция получает 409; суммы оплаты и кассы согласованы. |
| P2 | Повторное нажатие создания документа при медленном ответе отправляло несколько запросов. | Синхронная блокировка запроса и формы; после ошибки можно повторить с прежним вводом. |
| P2 | Быстрая выплата поставщику могла восстановить ввод оплаты клиента из общего ключа `new`. | Отдельные ключи восстановления по контексту быстрого создания. Ручная смена направления в том же черновике восстанавливается. |
| P2 | Открытие оплаты из устаревшей строки журнала обходило проверку актуальной серверной версии. | Перед подготовкой редактирования/распределения всегда загружается текущая оплата. |
| P2 | Изменение дочерних распределений без изменения `updated_at` оплаты не делало сохранённый ввод устаревшим. | Версия восстановления включает актуальные поля оплаты и распределения. |
| P2 | Позднее завершение сохранения могло закрыть другую форму или вернуть пользователя на оставленную страницу. | Обработчики проверяют текущий контекст и состояние страницы; очищается только ввод успешно сохранённой операции. Текущие фильтры журнала сохраняются. |
| P2 | Ручная смена типа документа в форме быстрого создания сохранялась локально, но отвергалась при восстановлении. | Валидатор принимает допустимый выбранный тип в том же контексте; остальные реквизиты восстанавливаются. |

В backend копирования и сводок дополнительных подтверждённых дефектов не найдено: источник копии блокируется, поля переносятся по списку, операция использует одну транзакцию и проверяет три разрешения. Сводка учитывает только проведённые распределения; складские отборы сохраняют ограничения роли.

## Проверка исправлений

- Проверены 52 браузерных сценария с тестовым API: 51 прошёл общим прогоном, один прошёл повторно после исправления утверждения о количестве чтений в React Strict Mode. Прикладной результат этого сценария был корректным и в первом прогоне.
- Прошли 112 серверных тестов документов, оплат, распределения, прав, логистики и копирования.
- Прошли три новых проверки одновременных операций на PostgreSQL: проведение перед изменением, проведение перед удалением, изменение перед проведением. Используется случайная отдельная схема с явным `schema_translate_map`; таблицы демонстрационной базы не изменяются.
- `npm run build`, Ruff и `git diff --check` прошли.
- Повторно прошли все 12 браузерных сценариев с настоящим PostgreSQL: документы, частичная и полная оплаты, касса, склад, восстановление, копирование и мобильное расхождение. Временный Docker проект удалён после прогона.

Новые проверки: `frontend/e2e/connected-payments.spec.ts`, `frontend/e2e/document-create-recovery.spec.ts`, `backend/tests/test_payment_mutation_concurrency.py`.

Команда PostgreSQL проверки в локальном backend контейнере:

